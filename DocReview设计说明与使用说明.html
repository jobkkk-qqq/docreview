DocReview V1.0

版本：V1.0　|　更新日期：2026-08-15　|　适用平台：Windows 10 / 11（64 位）
DocReview 是面向企业内部的数字档案管理系统，实现文档的上传、存储、分类、预览、下载、审核、权限控制与审计追溯全流程管理。系统以 Windows 便携版形式交付，双击即可运行，无需安装 Python、Node.js 等运行环境。

一、系统概述

系统核心能力一览：

📦 全生命周期管理 上传 → 分类 → 审核 → 预览 → 下载 → 删除 → 恢复
🔐 细粒度权限控制（RBAC） 角色权限、菜单权限、文档级/分类级权限四层控制
👁️ 在线预览 Office 自动转 PDF 预览，支持水印与移动端阅读
🔍 重复文件检测 基于 SHA-256 内容哈希，上传时自动提醒
📝 全程审计 登录、上传、下载、删除、审核等操作全部留痕
🛠️ 数据自修复 启动时自动扫描仓库，修复文件路径与 PDF 关联
🖥️ 系统托盘管理 常驻托盘，一键打开、查看日志、开机自启动、退出

二、系统架构设计

2.1 技术栈

层次技术选型
前端Vue 3 + Element Plus + Vite，单页应用（SPA）
后端Python 3.10 + FastAPI + SQLAlchemy（异步 ORM）
数据库SQLite（aiosqlite 驱动），单文件存储，自动迁移
桌面集成PyInstaller 打包，ctypes 实现 Windows 系统托盘
文档转换LibreOffice 命令行（soffice.com）后台异步转 PDF
水印渲染PyMuPDF（fitz），45° 斜角阵列水印
认证机制JWT（jose 库），Bearer Token 请求头

2.2 目录结构

DocReview-Windows/
├── DocReview.exe            # 程序启动入口（双击运行）
├── docreview.log            # 运行日志文件
├── 使用说明.txt             # 快速上手说明
├── backend/
│   └── docreview.db         # SQLite 数据库
├── frontend/
│   └── dist/                # 前端编译产物（请勿修改）
└── doc-repo/                # 文档文件存储目录
    ├── 2026/08/…            # 按年/月目录归档，文件名 UUID.扩展名
    └── draft/…              # 回收站目录（软删除文档暂存）

2.3 服务运行模式

程序双击启动后，在同一进程内拉起两个本地服务：

服务地址用途
前端静态服务http://127.0.0.1:3000提供浏览器访问的页面
后端 API 服务http://127.0.0.1:9002提供全部业务接口，含 /docs 在线接口文档
💡 启动流程：后端线程 → 前端线程 → 系统托盘（主线程）。后端启动时自动执行数据库建表、schema 迁移、文档仓库扫描修复三项初始化工作。

数据库共 11 张核心表：

表名说明关键字段

user_roles用户-角色关联user_id、role_id（多对多）

2.5 关键设计机制

🗑️
软删除与回收站：文档删除时物理文件移入 doc-repo/draft/ 目录，数据库标记 is_deleted，管理员可在系统配置页恢复。
📁
文件存储命名：上传文件以 年/月/UUID.扩展名 存储，UUID 命名避免重名冲突；原始文件名保留在数据库字段中。
🔄
数据库自动迁移：system_configs 表记录 schema_version，启动时若版本落后则依次执行迁移（当前 v5）。v5 迁移为既有文档新增 doc_level 字段（三级分类/文档级别，默认"无级别"），并为二级部门分类新增 department_id 字段（存量数据初始为空，归属部门由使用方后续维护）。
👁️
权限可见性过滤：普通用户只能看到公开分类文档、本人上传的文档、以及被显式授权的文档；超级管理员可见全部。

三、功能模块设计

3.1 认证与账号

功能接口说明
用户登录POST /auth/login用户名+密码校验，签发 JWT
令牌刷新POST /auth/refresh延长会话有效期
用户登出POST /auth/logout注销会话
修改密码POST /auth/change-password校验原密码后更新
重置密码PUT /users/{id}/reset-password管理员为用户重置（≥6 位）
💡 前端路由守卫拦截未登录访问，Token 存于 localStorage，请求自动携带；401 时自动跳转登录页。

3.2 用户与部门管理

用户管理（系统管理员）

  • 用户新增、编辑、彻底删除（硬删除）
  • 分配主角色 + 多个附加角色
  • 启用 / 禁用账号、重置密码
  • 按关键词、部门、角色、状态组合筛选

部门管理（系统管理员）

  • 部门增删改查，部门树展示
  • 用户归属部门，用于批量授权场景

3.3 角色与权限管理（RBAC）

权限体系共四层：

  1. 1
    角色-功能权限：每个角色可勾选菜单功能权限（如"文档管理""上传文档""用户管理"），形成菜单功能树
  2. 2
    业务角色默认权限：业务角色（quality/admin/hr/finance 等）自动继承对应业务范围的默认权限，无需逐项配置
  3. 3
    文档级权限：单篇文档可授予用户/角色"查看、下载、编辑、打印"权限
  4. 4
    分类级权限：分类可设置"全员可见"，或按用户/角色授权查看、编辑
⚡
权限矩阵页是核心配置入口：Tab1 菜单功能权限按角色勾选，带乐观锁（permission_version）防并发冲突；Tab2 文档权限按分类分组，逐文档勾选预览/下载/编辑/删除，支持整行全选。

3.4 分类管理（三级分类结构）

系统将文档划分为三级分类，用于更精细地组织与定位文档：

级别名称数据来源说明
一级文档分类分类管理页维护现有的文档分类，可绑定业务类型、全员可见、排序，用于上传、权限控制
二级部门分类引用部门管理中的部门文档可归属到具体部门；部门在"部门管理"中维护，分类管理页只读展示
三级文档级别系统预设固定值固定为 Ⅰ级文件、Ⅱ级文件、Ⅲ级文件、Ⅳ级文件、无级别，用于文档分级标识

一级分类功能

  • 分类增删改查，支持排序与启用/停用
  • 每个分类可绑定业务类型（quality/admin/hr/finance/legal/procurement/production）
  • 开启"全员可见"后所有登录用户默认可查看该分类文档
  • 业务用户的分类下拉自动推荐匹配其业务类型的分类
🗂️ 分类管理页顶部以"三级分类结构"卡片呈现整体层级概览：一级文档分类（下方表格维护）、二级部门分类（展示部门名称并可跳转至部门管理）、三级文档级别（固定预设）。部门和文档级别不参与权限校验，沿用原一级分类的权限体系。

3.5 文档管理（核心模块）

功能说明
单文件上传填写标题（必填）、编号（自动生成年月+流水号）、一级分类、部门（二级，选填）、文档级别（三级，默认无级别）、密级、描述；可选授权角色
批量上传统一的一级分类/部门/文档级别/密级/描述/授权角色，多文件提交，标题自动取文件名；结果对话框展示成功/失败明细
上传校验白名单格式（pdf/doc/docx/xls/xlsx/ppt/pptx/txt/jpg/png/zip/rar）、单文件 ≤50MB（可配置）；文档级别须为预设五级之一，部门须存在且启用
重复检测上传时计算 SHA-256，与库中未删除文档比对，重复则 409 提示并显示已存在文档，可跳转查看
列表浏览按一级分类分组展示（可折叠）；卡片/列表双视图；关键词+一级分类+部门+文档级别+密级组合搜索；组内分页（每分类独立翻页，每页30条，翻页只刷新当前组不影响其他组）
详情查看编号、标题、一级分类、部门、文档级别、密级、上传人、时间、大小、格式、描述
在线预览Office 后台转 PDF 后内嵌预览；PDF 直接预览；txt/md 文本预览；图片预览；移动端走浏览器原生阅读器
水印保护非公开文档预览时叠加"用户名+日期"斜角水印
下载权限校验后返回文件流；预览/下载行为均记录日志
编辑修改编号、标题、描述、一级分类、部门、文档级别、密级（需 modify_doc 权限）
审核待审核文档可审核为通过/驳回（approved/rejected），留审核意见
删除软删除，文件移入回收站（需 delete_doc 权限）
恢复系统配置页"文档恢复"区，仅超级管理员可恢复已删除文档
权限管理单文档授权/撤销；多选批量授权（按部门、按用户、按角色）
打印日志打印行为上报审计（print_doc）

3.6 文档预览与转换

  • Office 文件（doc/docx/xls/xlsx/ppt/pptx）上传后由 LibreOffice 命令行在后台异步转换为 PDF，不阻塞上传流程；转换失败不影响上传成功
  • 转换产物以同名 .pdf 保存在原文件同目录
  • 预览接口对非公开文档动态生成带水印的 PDF 临时文件，预览结束自动清理
  • 仓库自修复：应用启动时后台扫描 doc-repo/，为已有 Office 文档自动关联磁盘上存在的 PDF（按 UUID 同名匹配），修正失效路径

3.7 文件去重机制

  • 上传时计算文件内容 SHA-256 哈希，存入 documents.content_hash
  • 重复定义：与任意未删除文档哈希值相同即视为重复
  • 单文件上传触发 409 冲突时，前端弹出"文件重复提示"对话框，用户可选择取消或查看已存在文档
  • 批量上传时，重复文件在结果列表中标记为黄色"文件重复"提示
  • 历史数据兼容：v4 数据库迁移自动回填存量文档的 content_hash

3.8 仪表盘

  • 统计卡片：文档总数、近 7 天新增、分类数量、用户数量
  • 最近上传文档列表（10 条）
  • 快捷搜索与常用操作入口（按权限显示）

3.9 操作日志（审计）

  • 全量记录：登录、登出、上传、下载、删除、打印、预览、审核、新增、修改等 10 类操作
  • 记录维度：操作人、操作类型、资源类型与 ID、详情（JSON）、IP、时间
  • 支持按用户名、操作类型、时间范围筛选；分页浏览
  • 支持导出审计日志

3.10 系统配置

配置项说明
文档存储路径服务端绝对路径，可在界面修改
单文件大小限制1–500 MB，默认 50 MB
文件类型白名单可多选并自定义扩展名
启用水印 / 水印文字控制预览水印
自动审核开启后公开文档上传自动通过审核

3.11 系统托盘（桌面集成）

  • 程序常驻 Windows 托盘，不显示命令行窗口
  • 左键单击：浏览器打开系统
  • 右键菜单：打开 DocReview / 查看运行日志 / 开机自启动开关 / 停止服务并退出
  • 悬浮提示实时显示后端健康状态
  • 开机自启动通过注册表实现，带 60 秒延迟参数，等待系统就绪

3.12 数据自修复机制

🔧
针对管理员直接操作文件系统导致的脏数据，系统提供两类自动修复：
  • 列表中物理文件已不存在的文档 → 自动标记为已删除
  • 已删除列表中物理文件已不存在的记录 → 自动永久清理（避免"文件无法恢复但仍显示"的脏数据）

四、使用说明

4.1 安装与启动

  1. 将 DocReview-Windows 文件夹整体复制到目标电脑任意位置（建议路径不含中文和空格）
  2. 双击 DocReview.exe，程序自动启动前后端服务（无黑色窗口）
  3. 浏览器访问 http://127.0.0.1:3000 打开登录页（程序启动后不再自动打开浏览器，可单击托盘图标）
  4. 使用管理员账号登录

4.2 登录

  • 输入用户名与密码（密码至少 6 位）
  • 登录后页面按角色权限自动显示可用菜单
  • 登出后自动清理本地会话

4.3 普通用户日常操作

  1. 上传文档：进入"文档上传"，选择单文件或批量模式，填写一级分类、部门、文档级别与密级后提交；若文件重复会收到提示
  2. 查找文档：进入"文档管理"，使用关键词/一级分类/部门/文档级别/密级组合搜索；或按分类展开浏览
  3. 预览文档：点击文档行"预览"，Office 文件自动转 PDF 展示，预览页带个人水印
  4. 下载文档：点击"下载"，浏览器保存文件
  5. 查看操作记录：被授权后可查看操作日志，掌握文档动态

4.4 管理员日常操作

  1. 账号管理：用户管理页创建账号、分配部门与角色、启用禁用、重置密码
  2. 权限配置：权限矩阵页为角色配置菜单功能与文档权限
  3. 文档管控：文档管理页可编辑、删除任意有权文档；系统配置页可恢复回收站文档
  4. 系统配置：调整存储路径、文件大小限制、水印、自动审核等
  5. 审计追溯：操作日志页按条件检索全量操作记录并导出

4.5 数据备份与迁移

升级或迁移时请备份以下内容：

需备份位置
数据库backend/docreview.db
文档文件doc-repo/ 整个目录
✅ 备份后在目标机器启动即可恢复全部数据与文件。

4.6 常见问题

Q1
双击后浏览器没有自动打开？
新版已取消启动自动打开浏览器，单击系统托盘图标或手动访问 http://127.0.0.1:3000 即可。
Q2
上传的 Office 文件无法预览？
系统依赖 LibreOffice 将 Office 转 PDF。若目标电脑未安装 LibreOffice，可在标准安装路径安装，或将便携版放入程序目录 libreoffice/program/ 下。
Q3
文件上传提示"文件重复"？
说明相同内容的文件已存在于系统中。可在提示框中查看已存在文档，确认后取消上传，避免重复归档。
Q4
管理员在磁盘上删了文件，用户端列表未更新？
系统具备自修复机制：列表刷新时自动检测物理文件缺失并标记删除；已删除列表中的无效记录会自动清理。
Q5
如何修改端口？
在 DocReview.exe 同级目录新建 .env 文件：
BACKEND_URL=http://127.0.0.1:9002
FRONTEND_URL=http://127.0.0.1:3000
Q6
能否开机自启？
托盘图标右键 → "开机自启动" 勾选即可，开机后延迟 60 秒启动服务。
